# 周整理 Prompt

这份 prompt 只负责“单次执行”。

长期规则、目录约束、frontmatter 规范、允许与禁止事项，统一以 [LLM维护手册.md](../LLM维护手册.md) 为准。

```text
你现在要执行一次“周整理”。

在开始前，先读取并遵循：
- LLM维护手册.md

先明确：起止日期（默认截至目标日的最近 7 个自然日）。日期不明确且无法从当前请求推断时，再询问。
输出位置：总结/YYYY/YYYY-MM-DD周回顾.md，其中日期为区间结束日；有同范围文件时优先更新。

执行约束：
- 只使用明确属于本范围的素材；文件修改时间不能代替事件日期。
- 检查已有整理结果，只补增量，避免重复追加。
- 缺失记录如实注明，不能补造经历、成果或个人判断。
- 保留来源链接，区分用户决定与 AI 建议。
- 数量以真实材料为准，不为满足 3 到 5 个点而编造。
- 不默认创建定时任务、提交或推送；按用户明确授权执行。
- 收尾检查 YAML 属性、链接和 Git 差异，说明未完成的核验。

本次输入范围：
- 最近 7 天的日志：日志/YYYY/YYYY-MM-DD.md
- 最近 7 天新增或更新过的感悟、知识、展望笔记
- 如果已有相关周回顾，也可以一起读取

本次任务目标：
1. 汇总最近 7 天最重要的输入和变化；
2. 生成一份克制、可复核的周回顾；
3. 标记值得继续沉淀的主题；
4. 不删除原始记录，不编造成果。

请按下面步骤执行：
1. 概括本周最重要的 3 到 5 个主题；
2. 归纳：
   - 本周学到了什么
   - 本周最重要的进展
   - 本周卡住的地方
   - 值得升级成长期笔记的主题
   - 下周最重要的三件事
3. 生成或更新本周回顾到 `总结/`
4. 如果本周反复出现某个问题或判断，更新相关的 `感悟/` 或 `展望/`
5. 列出仍然需要我确认的内容

最后输出：
- 你更新了哪些文件
- 你新建了哪些文件
- 哪些内容还需要我确认
```

## 使用方式

AI 能访问本仓库时，直接指定本提示词和日期范围，由 AI 读取以下文件；不能访问时再提供这些材料：

- `提示词/周整理Prompt.md`
- `LLM维护手册.md`
- 最近 7 天的日志
- 相关的感悟 / 知识 / 展望
- 可能会被更新的周回顾
