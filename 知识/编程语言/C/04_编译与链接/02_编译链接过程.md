# 学习笔记： C语言编译链接过程

## 学习目标

理解 C 程序如何从源文件变成可执行程序，能区分编译错误、链接错误和运行时加载错误。具体平台的库搜索顺序和配置参数，遇到实际问题时再查。

## 从源代码到运行

通常可以把构建和运行分成以下几个阶段：

1. **预处理**：展开头文件、宏和条件编译指令。
2. **编译**：检查语法和类型，将代码转换为目标平台的汇编代码。
3. **汇编**：生成目标文件，其中包含机器代码、符号和重定位信息。
4. **链接**：把目标文件与需要的库组合起来，解析符号引用并处理地址，生成可执行文件。
5. **加载与运行**：操作系统加载程序；使用动态库时，还需要加载相应的库并完成必要的动态链接工作。

这是便于理解的典型流程，工具链可以合并部分步骤。加载不属于编译阶段。

## 为什么需要链接

一个程序可以拆成多个 `.c` 文件，各自编译，再链接到一起。

例如，`main.c` 调用 `add` 函数，`math.c` 提供它的实现：

- 头文件里的函数声明告诉编译器如何检查调用。
- `math.c` 中的函数定义提供实际实现。
- 链接器把调用与实现对应起来。如果没有把实现所在的目标文件或库加入链接，即使声明正确，也可能出现“未解析的外部符号”。

链接时需要理解两个术语：

- **符号解析**：找到函数或全局变量引用所对应的定义。
- **重定位**：根据最终布局，调整需要修正的地址引用。

## 静态库与动态库

| 方式 | 基本含义 | 使用时需要注意 |
| --- | --- | --- |
| 静态链接 | 将所需的库目标代码链接进最终程序 | 运行时不需要再提供这份静态库文件；更新库通常需要重新链接程序 |
| 动态链接 | 库代码保留在独立文件中，加载或运行时建立关联 | 部署时需要提供兼容的动态库及其依赖 |

**构建时能找到库，不代表运行时一定能找到动态库。** 两个阶段的查找配置是不同的。

## 遇到错误时先判断阶段

- **编译错误**：先检查语法、类型、声明和头文件。
- **链接错误**：先检查函数是否有定义、目标文件或库是否参与链接、是否存在重复定义。
- **运行时加载错误**：先检查动态库及其依赖是否齐全，以及平台和架构是否匹配。

## 与 Unity / C# 的联系

这些概念主要用于理解底层程序构建，以及以后接触 Unity 原生插件时排查问题。C# 托管程序集与 C/C++ 原生动态库即使都使用 `.dll` 后缀，也不是同一种库，不能直接套用同一套加载规则。

当前先掌握上述区别；平台专属的加载机制和路径配置，等实际接入原生插件时再学习。
